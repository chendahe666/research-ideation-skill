# Stage 4–5：研究问题与 idea 发散

## Stage 4 · 话题 → 问题 → 意义

**阶梯**（来自李沐《研究的艺术》，改编自 *The Craft of Research*）：
1. **话题**：从兴趣出发，读和挖，缩到一个有边界的话题
2. **问题**：用 5W1H 追问（谁、在什么情境、什么变量、怎么影响、为什么），把话题变成问题
3. **意义**：不断追问 *So what?* 和 *If not?*（不解决的话读者要付出什么代价）

写成一句话：
> 我研究 **[话题]**，因为我想弄清 **[问题]**，以便帮助读者理解 **[意义]**。

**同一个方向的两个层级：**

| 层级 | 教育例子 | 3D 水印例子（写法演示，需核查） |
|---|---|---|
| 热门话题（不能直接研究） | AI 改变教育 | 3D 内容的版权保护 |
| 仍然太宽 | 生成式 AI 如何影响学习？ | 怎么给 3DGS 加水印？ |
| 可研究的问题 | 在大学编程课里，使用 GenAI 助手对**低/高先验水平**学生的**自我调节学习策略**有什么不同影响？机制是**认知卸载**，还是**反馈时效**？ | 当 3DGS 资产被**转换表示**（转成 mesh / 重新训练 / 蒸馏进生成模型）之后，现有水印的可追溯性会怎样衰减？能否设计出**对表示转换不变**的水印？ |

**合格的研究问题要过 5 项检查：**
- [ ] 有明确的对象、情境、变量或构念、对比
- [ ] 可以证伪：写得出"如果结果是 X，我的假设就错了"
- [ ] 有决定性实验：一个实验就能大体回答
- [ ] 有意外性：写得出"什么结果会让同行意外"
- [ ] 能对上 gap 台账里至少一个 ID

`04_research_questions.md`：每个 gap 写 1–3 个研究问题，每个研究问题都附上面的 5 项检查结果。

## Stage 5 · 发散算子

每批只用一类算子，一批生成 8–15 个 idea 标题加一句话描述。

### A. Jia-Bin Huang 的 7 种方法（X thread, 2021）
| 算子 | 做法 | 例子 |
|---|---|---|
| 换个维度 | 换模态或维度：text / audio / image / video / 3D / 4D / graph | 2D 图像水印 → 3D → 4D 动态场景 |
| 放松假设 | 去掉前人的限制条件，让方法更通用 | 不需要访问原始训练数据 |
| 增加假设 | 利用某个具体问题的领域知识，把通用方法特化 | 利用 3D 几何的多视角一致性 |
| 组合 | 把两个想法或问题合并 | 一定要说清组合带来的新性质 |
| 拿锤子找钉子 | 把社区新出的强大工具用到你的问题上 | 新的 foundation model 或 feed-forward 3D 重建 |
| 加形容词 | slow→fast、batch→online、sensitive→robust、centralized→distributed、data-hungry→data-efficient | "免训练"、"可公开验证"、"实时" |
| 压力测试 SOTA | 用非标准的真实样本测，暴露失败 | 这就是 Stage 3 的第 4 类证据源 |

### B. ResearchStudio-Idea 的 15 种模式（从 ICLR / ICML / NeurIPS 2021–2025 的 1947 篇论文，包括 oral、高引和被拒稿件，归纳而来）
1. 审视并翻转一个假设
2. 替换算子或表示
3. 把固定的生成组件变成可学习的
4. 设计能隔离混杂因素的诊断实验
5. 把异构输入统一到同一空间
6. 把问题重构成可解的对象
7. 人工制造监督信号
8. 通过构造把结构编码进模型
9. 证明等价性来统一不同方法
10. 分解问题，分别处理
11. 分解问题，交给专门的求解器
12. 把离散搜索松弛成连续优化
13. 用条件化代替重训练来做适配
14. 先刻画极限，再突破它
15. 为目标性质设计专门的 pretext 目标

### C. 其他算子
| 算子 | 来源 | 做法 |
|---|---|---|
| 挑战假设 | Sandberg & Alvesson | 把 G2 找到的共享假设反过来，重新定义问题 |
| Facet 重组 | Scideator | 把论文拆成 目的 × 机制 × 评测 三个 facet，跨论文重新组合；类比来源要同时有近领域和远领域 |
| 链外推 | Chain of Ideas | 沿 Stage 2 的每条演化链预测下一环 |
| 目标倒推 | Schulman（goal-driven） | 先设想"两年后希望出现的能力"，再倒推今天要解决的子问题 |
| 极简化 | 常见经验 | 能不能用简单得多的方法达到 SOTA？找到复杂方案里真正起作用的那个核心 |
| 诊断/分析型 | 模式 4 | 不提新方法，而是回答"现有方法为什么有效或失败" |
| 新 benchmark / 新威胁模型 | Stage 3 第 9 类证据源 | 领域测错了东西，或者防的攻击太弱 |
| 反向使用 | 常见经验 | 把防御变攻击，或者把攻击变防御（水印 ↔ 去水印、检测 ↔ 规避检测） |

### 多样性协议（针对"LLM idea 大量重复"的问题）
1. 每批只用一类算子，prompt 里附上"已生成的 idea 标题列表"，要求新 idea 和它们在**机制**上不同，不是换个说法
2. 每批结束后做聚类去重：机制相同、只是场景不同的算一个，合并
3. 用不同的 persona 发散，例如"信息隐藏老教授"、"做生成模型的新人"、"工业界安全工程师"
4. 类型配额：方法、分析、benchmark、理论、系统至少覆盖 4 种；反共识的 idea ≥2 个
5. 只对保留下来的 idea 做 CoT 深入展开

### 发散提示词
```
Gap/RQ：<G? / RQ?>
领域地图摘要：<5 行>
已生成的 idea 标题（不要重复它们的机制）：<列表>
本轮算子：<算子名 + 说明>
请生成 10 个 idea。每个 idea 给出：标题 | 一句话机制 | 针对哪个 gap | 为什么以前没人做（或做不了）| 最大风险。
要求：至少 3 个你认为"大多数同行第一反应会反对"但你能给出理由的；不要写 "A+B" 式拼接，除非能说清组合会产生什么新性质。
```

## Idea 卡片模板（`05_idea_pool.md`，挑 5–8 个写成完整卡片）

```markdown
### I-<n>：<标题>
- **一句话洞见**（不显然的"为什么会有效"）：
- **针对的 gap**：G?（类型：__）
- **研究问题**：我研究 __，因为我想弄清 __，以便帮助读者理解 __。
- **现有方法为什么不行**：[最接近的工作 1/2/3 + 各自的具体局限，带出处]
- **方法 / 研究设计**：
- **Why now**：什么新技术、新数据、新需求或新法规让它现在变得可行或重要？
- **实验计划**：数据集 | baseline | 指标 | 关键消融 | 压力测试
- **成功是什么样**（写出预期的主表或主图）：
- **什么结果会证伪它**：
- **最小验证实验（≤2 周）**：
- **Fallback**（主方案失败时，论文还能讲什么）：
- **资源需求 vs 我的画像**：
- **idea 类型**：方法 / 分析 / benchmark / 理论 / 系统
```

这个模板综合了 Si et al. 的 idea 格式（问题、动机、方法、分步实验计划、测试样例、fallback）、Heilmeier 问答，以及"一句话洞见"和"why now"两项。
