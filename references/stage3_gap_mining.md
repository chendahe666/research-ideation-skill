| # | 证据源 | 怎么拿 | 信号含义 | 注意 |
|---|---|---|---|---|
| 1 | 多篇论文的评审反复出现的同类弱点 | `openreview_reviews.py`，重点看 weaknesses / questions / limitations 字段，以及 meta-review 和被拒稿件 | 整个领域都有的缺口，审稿人会买账 | NeurIPS 只公开录用论文；ICLR 连被拒稿件也公开，信息量最大 |

| 5 | 论文之间结论矛盾 | 横向对比同一 benchmark 上的数字，以及不同论文的消融结论 | evidence gap | 先排除设定和实现上的差异 |

| 7 | 所有论文都没说出口的共同假设 | 让模型逐篇列出默认假设，再做交集 | problematization 的原料 | 最容易产出高影响力的问题 |

| 9 | 评测本身的缺口 | benchmark 饱和、指标和人的判断不一致、攻击集太弱、缺少统一 benchmark | 可以做 benchmark 或诊断型论文 | |

## Gap 分类法

**Miles (2017) 的 7 类 gap**，括号里是 CS/AI 中常见的例子：
- **Evidence gap**：各研究的结论单独看成立，放在一起看却互相矛盾（同一方法在不同论文里鲁棒性相差很大）
- **Knowledge gap**：想要的发现根本不存在（没有人研究过 X 在 Y 条件下的行为）
- **Practical-knowledge conflict gap**：实践做法和研究结论不一致，或者研究没覆盖到（工业界用的格式或流程，学术界没考虑）
- **Methodological gap**：方法本身限制了结论，换一种方法可能得出不同结论（大家都只用渲染图来评测水印）
- **Empirical gap**：主张没有被实证检验，或者只在 toy 设定下验证过
- **Theoretical gap**：现象缺少理论解释，或者理论没被检验（为什么某种嵌入方式更鲁棒？）
- **Population gap**：某类对象或人群研究不足（CS 里可以是某种数据域、表示、模态、语言、设备；教育里可以是某个学段或先验水平的学生）

**Sandberg & Alvesson (2011) 的 gap-spotting 模式**：
- **Confusion spotting**：已有文献互相矛盾
- **Neglect spotting**：被忽视的领域，研究不足，或者缺少实证支撑
- **Application spotting**：把已有理论或方法延伸、补充到新情境

**Problematization（挑战假设）**，按假设的层级从低到高：
- In-house：某个学派内部的默认做法（"水印一定要在训练时嵌入"）
- Root metaphor：看问题的底层隐喻（"水印是一种信号"，那它可不可以是一种"行为"？）
- Paradigm：本体论和认识论层面的前提
- Ideology：价值立场（谁的利益被当成默认目标）
- Field：整个领域共享的前提（"攻击者不知道水印算法"）

Davis (1971) 在 *That's Interesting!* 里提出：让人觉得有意思的理论，否定的是读者"弱持有"的假设。太显然的假设不值得挑战，读者深信不疑的又很难说服。

## `03_gap_ledger.md` 模板

```markdown
| ID | Gap 陈述（一句话） | 类型 | 证据（≥2 条，引文+链接） | 谁受影响 / 为什么重要 | 近期是否已被填补（检索日期 + 最接近的工作） | 对我的可做性 | 热度 |
|---|---|---|---|---|---|---|---|
| G1 | | Methodological + Field 假设 | R: [评审原文] (ICLR'25 xxx); L: [局限原文] (arXiv xxxx) | | 未见 (2026-09-24 查) / 部分: [论文] | 高/中/低 + 理由 | ↑/→/↓ |
```

下面是每一列的规则：
- 证据列写"R: 评审 / L: 作者局限 / S: 压力测试 / C: 矛盾 / P: 实践 / A: 共享假设 / X: 跨领域 / E: 评测"加上原文短引和链接。只有一个来源的 gap 标 `弱`。
- "近期是否已被填补"这一列必须真的去检索过才能填，不能凭感觉。
- 最后按 **证据强度 × 重要性 × 对我的可做性** 排序，挑前 5–8 个给用户。

## 提示词

### G1 · 聚类评审弱点
```
下面是 <venue/年份> 中与 <子方向> 相关的 N 篇投稿的评审 weaknesses/questions 原文。
1. 把这些弱点聚成 5–10 类，每类给名称、出现次数、覆盖了几篇论文、2 条代表性原文（附论文标题）。
2. 区分"单篇论文的实现缺陷"和"反复出现的领域级缺口"，只有后者进入 gap 候选。
3. 对每个领域级缺口，说明被拒论文和被录用论文在这一点上有没有差别。
4. 标出评审明确要求、但没有任何论文做到的实验或能力。
```

### G2 · 共享假设提取（problematization）
```
逐篇列出这些论文的默认假设（威胁模型、数据分布、表示形式、评测协议、用户行为、部署环境），
然后找出 ≥80% 的论文都共享的假设。对每个共享假设：
(a) 它在现实中成立吗？给出反例场景；
(b) 如果把它反过来，会冒出什么新问题？
(c) 按 Davis 的 "That's interesting" 标准，挑战它算"有意思"还是"显然"？
(d) 它属于哪个层级（in-house / root metaphor / paradigm / ideology / field）？
```

### G3 · 矛盾与证据缺口
```
对比这些论文在同一 benchmark/设定上报告的结果和消融结论，找出互相矛盾的地方。
对每处矛盾，给出可能的解释（设定、实现、指标、数据的差异），并设计一个能判定谁对的最小实验。
```

### G4 · 跨领域迁移
```
领域 A（我的）：<演化链>
领域 B（相邻）：<演化链>
找出 B 中已经成熟、A 中还没有的 3–5 个概念或技术。对每一个：直接迁移会在哪里失败（A 的特殊性）？
为了克服这种失败需要做哪些改造？这个改造本身就是贡献。
```

### G5 · 近况核查（每个 gap 都要做）
```
Gap：<陈述>
给出 5 组不同措辞的检索式（同义词、上位词、相邻领域说法），分别用于 arXiv（近 12 个月）、
OpenReview（当年和上一年）、Google Scholar。列出检索到的最接近的工作，
逐条判断：已填补 / 部分填补（剩下什么）/ 没有填补。
```

## 例子：同一个话题，gap 陈述写得好和写得差

- 差："3D 水印的鲁棒性还有待提高。"（没有对象、证据和标准）
- 好："现有 3DGS 水印的鲁棒性评测只覆盖渲染图层面的 2D 攻击（噪声、JPEG、裁剪），没有评测资产被转成 mesh 或被再次训练之后，水印还能不能提取出来。[证据：评审 R1/R3 追问 …；作者局限 L2 …] [近期核查：…]"（**这里只是演示写法，不代表这个 gap 真实存在，必须按 G5 核查**）
