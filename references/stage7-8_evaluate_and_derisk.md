# Stage 7–8：查新、评估、去风险

## Stage 7 · 查新协议（`07_novelty_check.md`）

借鉴 ResearchStudio-Idea 的 Scoop-Check，把 idea 拆成 4 个轴分别查：

| 轴 | 问题 | 检索式（每轴 3–5 种说法） |
|---|---|---|
| 问题框定 | 有没有人把问题定义成一样的？ | |
| 核心机制 | 有没有人用过同样的机制，哪怕是在别的问题上？ | |
| 关键洞见 | 有没有人提出过同样的"为什么有效"？ | |
| 应用领域 | 同样的机制在相邻领域有没有人做过？ | |

**必查的检索源**：OpenAlex（`lit_scan.py`）、Semantic Scholar、arXiv 最近 6–12 个月（用 WebSearch，站点限定 arxiv.org，按时间排序）、OpenReview 当年和上一年的投稿（`openreview_reviews.py`）、Google Scholar，以及领域内常用的项目页或 GitHub。AI Scientist 的做法是最多迭代 10 轮检索，每轮 10 条结果，然后才下结论，这里照做。

**输出：**
```
| 最接近的工作 | 年份/venue | 问题框定 | 机制 | 洞见 | 领域 | 差异总结 |
|---|---|---|---|---|---|---|
| | | 同/异 | 同/异 | 同/异 | 同/异 | |

结论：新颖 / 部分重叠（需要重定位：__）/ 已被做过（放弃，或者转成对比或分析型工作）
检索日期：____
```

## 评分表

每项 1–5 分，附锚点说明。**用它来讨论，不要机械加总。**

| 维度 | 1 分 | 5 分 | 出处 |
|---|---|---|---|
| 重要性 | 只有作者自己在乎 | 解决了会改变社区或实践的做法 | Hamming；Heilmeier "Who cares?" |
| 新颖性 | 查新发现几乎一样的工作 | 4 个轴里至少 2 个有实质差异 | Scoop-Check |
| 洞见 | 说不出为什么会有效 | 有一个不显然、能一句话说清的洞见 | |
| 可行性（针对我） | 需要我没有的关键资源 | 两周内能拿到第一个信号 | Hamming "reasonable attack" |
| gap 证据强度 | 只有一篇论文的 future work | 评审 + 局限 + 压力测试多源印证 | Stage 3 |
| 时机 | 过时，或者太早（前置条件还没具备） | 刚有了使能条件，赛道还没挤满 | Jason Wei：热点上做得更好，或者赌下一个热点 |
| 可延展性 | 做完就结束了 | 能自然长出 2–3 篇后续工作 | Karpathy："fertile ground" |
| 优势匹配 | 谁都能做 | 用上了我的不公平优势 | |
| 执行风险（反向计分） | 高：主结果很可能是 null | 低：主结果不成立时 fallback 仍然有价值 | Ideation–Execution Gap |

**比较多个 idea 时用两两比较**："如果只能做一个，选 A 还是 B？为什么？"每次比较只写一句话理由。可以做成 Elo 或 Swiss 赛制。

**"别人发表"检验**：如果另一个组明天发表了这篇论文，你会兴奋地去读，还是会觉得"嗯，意料之中"？

## 淘汰标准（命中任意一条就砍掉或重构）
- 最近 12 个月已经有人做过，而且说不出实质差异
- 没有可测的成功标准，也写不出会证伪它的结果
- 关键资源拿不到
- 唯一的新意是"A+B"，说不出组合带来的新性质
- 支撑 gap 的只有一个来源，而且这个来源是论文的 future work
- 用户自己不感兴趣（研究要做 6–12 个月，兴趣是硬约束）

## Stage 8 · 去风险计划与一页提案（`08_proposal.md`）

### Heilmeier 8 问（第 1 问不许用术语）
1. 你想做什么？（不用任何术语）
2. 现在是怎么做的，有什么局限？
3. 你的方法新在哪里，为什么你认为它会成功？
4. 谁会在乎？如果成功了，会带来什么不同？
5. 有哪些风险？
6. 要花多少成本？
7. 要花多长时间？
8. 期中和期末用什么"考试"来检验是否成功？

### 风险排序（Steinhardt：按单位时间的信息量排序）
```
| 风险假设 | 失败概率 | 验证所需时间 | 失败时的损失 | 优先级 = 失败概率 / 验证时间 |
```
最可能失败、又最快能验证的，最先做。有两种工作状态：
- **去风险模式**：尽快找出这个问题是不是不可行
- **执行模式**：假设问题可行，尽快把它做出来

越早排除死路，留给可行方向的时间就越多。

### 两周试点
```
第 1–3 天：复现最接近的 baseline（拿到可信的对照数字）
第 4–7 天：用最小实现验证风险最大的假设
第 8–10 天：跑一个压力测试或关键消融
第 11–14 天：整理结果，写出摘要和 Figure 1 草图，做 go / no-go 判断
Go：__（写成可量化的阈值）
No-go：__
No-go 之后：fallback 方案 / 转成分析型论文 / 回到 gap 台账挑下一个
```

### 写作检验（写不出来就说明没想清楚）
- **摘要初稿**：背景一句 → gap 一句 → 洞见一句 → 方法一句 → 结果（写预期的结果）一句 → 意义一句
- **Figure 1 草图**：一张图说清"现有方法在哪里失败，我们的方法为什么不会"
- **Jia-Bin Huang 的 Introduction 模板（3 张图 + 5 个问题）**
  - 3 张图：WHAT 图展示输入和输出，说明你做成了什么；WHY 图用具体例子展示现有方法的问题；HOW 图说明方法怎么运作
  - 5 个问题：问题是什么？别人做了什么？gap 在哪？你做了什么？你的贡献是什么？
  - 如果选题阶段就画得出 WHY 图，说明 gap 是实的

### 研究进行中（Neel Nanda 的三种模式）
- **探索**：还没有明确假设，目标是获取信息、扩大对问题的接触面。不要过早收敛
- **理解**：已经有了具体假设，目标是让自己相信它是真的还是假的
- **提炼**：目标是把发现压缩成能说服别人的严谨证据，然后写出来

每周回看实验笔记（Schulman：保持每日实验笔记，定期复盘），问自己现在处在哪个模式，做的事是否和这个模式的目标一致。
